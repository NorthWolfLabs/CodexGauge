### Final fixes

- **Concurrent subscriptions:** reproduced 24 simultaneous registrations all being accepted against the intended 16-device limit. Reserve each subscription before yielding to the receiver RPC, and use generation/revision checks so stale cleanup cannot remove a replacement registration. The regression now consistently accepts 16 and rejects 8.
- **Feed removal and rotation:** revoke access synchronously before remote cleanup, prevent an in-flight rotation from resurrecting deleted credentials, and retain only a generation counter so recreating an installation ID cannot collide with old receiver cleanup. Existing viewers are closed; old links stay rejected after recreation. Rotation closes old viewers before awaiting cleanup, preserving newly connected viewers.
- **Ordered live delivery:** broadcast and acknowledge a snapshot before yielding to push processing. A 20-frame burst with receiver activity arrives in order. The test fixture uses strictly increasing observation timestamps, avoiding accidental same-millisecond duplicate frames.
- **Unicode compatibility:** Swift bounds wire text by UTF-16 code units while preserving whole graphemes, matching the JavaScript schema. Actual Swift-encoded fixtures are validated with Zod. A pathological empty Mac name falls back to “Mac”.
- **APNs size:** cap complete JSON payloads at 4096 UTF-8 bytes, shortening body/title on grapheme boundaries only when necessary and preserving Mac/task routing. Tests include emoji, combining characters, JSON escaping, and long titles. The limit follows [Apple's notification payload guidance](https://developer.apple.com/documentation/usernotifications/generating-a-remote-notification).
- **Notification navigation:** task taps select Tasks and open the current detail by Mac/task ID; allowance taps reset Overview navigation. Malformed or unlinked notification routes are ignored. A task awaiting its first snapshot has a waiting state. Tapping a viewing link that cannot be added opens the correction form with the error visible.
- **Test-process cleanup:** stop the captured process tree without allowing Wrangler to respawn orphan workers; cleanup also runs after a failed check. A deliberately failed check confirmed cleanup and preserved the nonzero result. The local Workerd close-handshake grace period is allowed in the deletion test; it does not weaken the access-revocation assertions.

## Charts, Live Activities, and credits

The owner identified missing charts and Live Activities and requested credit balances. This pass adds the actual native features and their delivery paths. It does not establish final UI acceptance or physical ActivityKit behavior.

### Implemented

- **Activity charts:** native Swift Charts with 7/30/90-day ranges, selected-day values, totals, daily averages, calendar-correct date parsing and zero-filled days. Duplicate account observations are not added together.
- **Task throughput:** a five-minute chart in each task detail, with bounded samples, replay rejection and separate line segments after a connection gap. Samples are collected in memory while the phone is connected. Demo mode includes deterministic chart samples.
- **Credits:** exact Codex balance strings, decimal amounts, unlimited balances and explicit zero when reported. Credits are optional on the wire, preserving compatibility with older Mac snapshots. Overview, the medium Home Screen widget, Mac popover and Mac Limits view display them. Missing observations do not become a fabricated zero.
- **Native ActivityKit:** one activity per active Mac, Lock Screen and Dynamic Island views, waiting-task priority, working/waiting counts, task/project and Mac identification, throughput, stale state, and read-only deep linking. Completed/follow-up-ready tasks are excluded. Idle summaries do not repeat the same heading twice.
- **APNs lifecycle:** start, update and end payloads use the ActivityKit topic, activity tokens, bounded content and Unix timestamps. iOS 17.2+ can start remotely; iOS 17.0/17.1 starts in the foreground. Background rate-only updates are throttled to about one minute, foreground rate updates to five seconds, with state changes prioritized. The relay preserves an earlier delivery alarm if a new event arrives during APNs I/O.
- **Lifecycle recovery:** duplicate activity cleanup, user-dismissal suppression until the Mac becomes inactive, explicit off/on reset, bounded retry/start attempts, stale-Mac alarm suppression, end retries after stale observations, and activity-token expiry recovery. System-ended activities are distinguished from user dismissals.
- **Access changes:** usage-only links cannot register task activities. Removing or replacing a link ends local cards, live registration participates in unlink serialization, revoked streams end their local activity, and a rejected ActivityKit subscription ends its card. Late push-to-start arrivals for unlinked Macs are discarded. Relay revocation attempts a sanitized end push without old task titles.
- **Preview isolation:** static and local relay demo launches do not load real saved push subscriptions during application startup. The new chart/credits UI regression is prepared but not executed.
